# بستهٔ وردپرس: صفحهٔ اصلی Editorial Hybrid

این پوشه صفحهٔ اصلی، هدر و فوتر جدید grooming-dogs.com را با WP-CLI روی وردپرس نصب می‌کند.
همه‌چیز از روی پروتوتایپ `prototype/editorial-hybrid` ساخته شده است. این پوشه را دستی ویرایش نکنید؛
پروتوتایپ را تغییر دهید و دوباره بسازید:

```bash
python3 BUILD/editorial-hybrid/build.py
```

## محتویات

| مسیر | چیست |
|---|---|
| `templates/home-01…09-*.json` | هر بخش صفحهٔ اصلی یک قالب Elementor جدا (container با یک ویجت HTML) |
| `templates/header.json`، `templates/footer.json` | هدر و فوتر برای قالب‌های Header & Footer Builder |
| `templates/home-order.json` | ترتیب بخش‌ها روی صفحهٔ اصلی |
| `mu-plugins/gd-editorial.php` و `mu-plugins/gd-editorial/` | CSS و JS: هدر و فوتر در همهٔ صفحه‌ها، بقیه فقط در صفحهٔ اصلی |
| `media/` | ۱۴ عکس (Pexels) با متن جایگزین و نام عکاس، و آیکون سایت |
| `wp/*.php` | مراحل نصب، هرکدام با `wp eval-file` |
| `install.sh`، `rollback.sh` | نصب و برگرداندن در یک فرمان |

## نصب

۱. پوشه را روی سرور بگذارید، کنار وردپرس یا هر جای دیگر:

```bash
scp -r BUILD/editorial-hybrid/package user@server:~/gd-editorial
```

۲. اول فقط بررسی کنید. این مرحله هیچ چیزی را تغییر نمی‌دهد:

```bash
cd ~/gd-editorial
./install.sh --path=/path/to/wordpress --user=<نام کاربری مدیر> --check
```

بررسی می‌کند که Elementor و Header & Footer Builder فعال باشند، صفحهٔ اول GD-00 باشد، هدر و فوتر پیدا شوند،
پوشهٔ mu-plugins قابل نوشتن باشد و کاربر اجازهٔ ذخیرهٔ HTML بدون فیلتر را داشته باشد. این اجازه برای آیکون‌های SVG لازم است.

۳. نصب:

```bash
./install.sh --path=/path/to/wordpress --user=<نام کاربری مدیر>
```

گزینه‌ها:
- `--yes` بدون پرسیدن تأیید
- `--site-icon` آیکون شانه را آیکون سایت (favicon) می‌کند
- `--library` هر بخش را در Templates › Saved Templates هم ذخیره می‌کند

هر گزینهٔ دیگر مستقیم به `wp` داده می‌شود، مثلاً `--url=` در multisite.

نصب این کارها را به ترتیب انجام می‌دهد:
1. از صفحهٔ اول، هدر، فوتر و آیکون سایت نسخهٔ پشتیبان می‌گیرد، در `~/backups/grooming-dogs/editorial-hybrid/`.
2. mu-plugin جدید را کپی می‌کند. mu-plugin قدیمی `gd-home.php` پاک نمی‌شود؛ به `gd-home.php.off` تغییر نام می‌دهد.
3. عکس‌ها را یک بار وارد کتابخانهٔ رسانه می‌کند. اجرای دوباره همان‌ها را دوباره استفاده می‌کند.
4. بخش‌ها را با API خود Elementor روی صفحهٔ اول ذخیره می‌کند.
5. محتوای قالب‌های هدر و فوتر را عوض می‌کند. قوانین نمایش آن‌ها (Entire Website) دست نمی‌خورد.
6. کش CSS المنتور و کش وردپرس را خالی می‌کند. اگر کش صفحه دارید (LiteSpeed، WP Rocket، Cloudflare)، آن را هم خالی کنید.

اجرای دوبارهٔ نصب مشکلی ندارد. مثلاً بعد از ساخت دوباره، فقط محتوا و فایل‌ها به‌روز می‌شوند.

## برگرداندن

```bash
./rollback.sh --path=/path/to/wordpress --user=<نام کاربری مدیر>
```

سایت را به حالت پیش از *اولین* نصب برمی‌گرداند: صفحهٔ اول، هدر، فوتر، آیکون سایت و mu-plugin قدیمی `gd-home`.
برای برگشتن به یک نسخهٔ پشتیبان مشخص، `--backup=<پوشه>` را اضافه کنید. عکس‌های واردشده در کتابخانهٔ رسانه می‌مانند.

## نکته‌ها

- **منو:** هدر جدید منوی خودش را در HTML دارد و از منوی «Primary» وردپرس استفاده نمی‌کند. برای تغییر منو،
  `MENU` را در `prototype/editorial-hybrid/app.js` عوض کنید و دوباره بسازید.
- **سئو:** لینک‌های منو و فوتر در HTML سرور هستند. محتوای بخش‌های تعاملی صفحهٔ اصلی با JS ساخته می‌شود:
  جدول مو، ابزارها، مشکلات و مراحل انتخاب آرایشگر. گوگل این محتوا را اجرا و می‌خواند، و همه به راهنماهای اصلی لینک می‌دهند.
- **داده‌ها:** فایل‌های `content.js` و `data.js` از متن منتشرشدهٔ ۲۲ صفحه ساخته شده‌اند. اگر متن راهنماها عوض شد،
  پروتوتایپ را دوباره بسازید (`tools/extract_content.py`، `tools/build_data.py`) و بعد همین بسته را.
- **فونت‌ها:** Literata و Source Sans 3 را سایت از قبل بارگذاری می‌کند. این بسته فونتی از بیرون نمی‌آورد و هیچ درخواست خارجی، کوکی یا ذخیره‌سازی ندارد.
- **حالت تیره:** حذف شده است، چون صفحه‌های راهنما هم فقط حالت روشن دارند.
- **آزمایش‌شده** روی وردپرس 6.8.3 و Elementor 3.35.9 (نصب، نصب دوباره، برگرداندن، و ۳۷ بررسی در مرورگر روی دسکتاپ و گوشی).
  Header & Footer Builder در آزمایش با یک جایگزین ساده شبیه‌سازی شد. پیش از نصب روی سایت اصلی، یک بار روی staging اجرا کنید.
